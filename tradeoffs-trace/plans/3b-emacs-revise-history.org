* Phase 3b: minimal readable surface
  :PROPERTIES:
  :ID:          p3b-minimal-surface
  :CHECKS:      make -C tradeoffs-trace check
  :BOUNDARIES:  init.el
  :RESERVED:    the C-c m key prefix and existing Pilish bindings
  :END:
  Goal: core/init-tradeoffs-trace.el stays small and read-only apart from the input box: the decision view lists only decisions, each self-contained so the owner can pick it up in seconds; the trace and status show what agents are doing and where the time goes, without clicks or extra commands. The owner intervenes only through the input box (plan 2c).
  Acceptance:
  - C-c m d lists only decisions (worker-disclosed and reviewer-discovered); no action keys other than g (refresh), TAB (fold) and q (quit); the r/o/x/1-3/w/s/u keys and their commands are removed
  - a header line states the phase and review progress, e.g. "p2c · REVIEWING · M ✓ A ⧗ B ⧗ — votes not cast yet"
  - each decision is one self-contained block: a heading with its state (PENDING, ACCEPTED, ACCEPTED with dissent, REJECTED, SUSPENDED) and the choice (at most 80 characters, full sentence in the body); who raised it (worker, or reviewer M/A/B discovered); why it matters; the options with consequences, the chosen one marked; the recommendation; one line per reviewer ballot with its rationale; reviewers who independently discovered the same choice listed as "also seen by"
  - review progress shows each reviewer's outcome, not only that it submitted: approvals, rejections and findings raised (e.g. "M ✗ 2 reject · 1 blocking  A ✓  B ✓ 3 advisory"), and after RESOLVING the status states why the phase did or did not accept (e.g. "not accepted: M vetoed D-3; blocking finding F-M-4 open → repair attempt 2"); observed in run 4ec5e0f8: "M ✓ A ✓ B ✓" read as all approved while M had vetoed and a blocking finding was open
  - the decision view shows the current round only: a header line "Round N · candidate <short sha> · attempt N — addressing <open blocking findings and failed decisions>", the records bound to the current candidate labelled with the tally result from tt state (never inferred from individual ballots; observed: D-3 shown as DISSENT although M's veto failed it), and each earlier round collapsed into one line "Round N · <sha> · not accepted: <reasons>", expandable with TAB
  - findings are shown with a one-sentence heading, grouped by location with "also raised by", evidence folded
  - the status buffer and tt status show checks, probe and review results only for the current candidate; while a repair attempt is implementing they read "pending (round N)", with the previous round's outcome on its own line (observed in run 4ec5e0f8: attempt 2 IMPLEMENTING showed round 1's checks passed, probe passed and M/A/B submitted)
  - boundary triggers are not listed as decisions; the status buffer shows one line "boundary files changed: N (reviewers classify)"
  - empty sections are not shown
  - the trace renders each tool call as one line: time (HH:MM:SS), a verb ($ command for sh; read/grep/edit/write with path and range or pattern), ✓ or ✗ with exit code, duration and the last output line; a running call shows ⧗ with elapsed time; sleep/tail polling is marked "polling"; no blank lines between tools (observed: raw alists like "▸ tool: sh ((command . …" and blank lines)
  - the trace shows the files each tool call changed in the worker's worktree as one line per file, "path +added −removed" (git diff --numstat before and after), including files written by sh heredocs and redirects; no diff content
  - tt timing <run> (CLI, --json available) reports per agent: elapsed, tool vs model time, time per category (polling, full test runs, narrow tests, file writes, reads/greps, other) and the slowest calls; ~/.tradeoffs-trace/tools/tt-timing is the reference behaviour
  - the status buffer shows the phase pipeline as one line of stages with completed stages' durations, the current stage's live elapsed time, attempt and repair rounds, time to the stage deadline, and a Time line for the active agent (model %, polling %, full-test %, the running tool and its elapsed time, a warning when polling exceeds a quarter of the attempt)
  - a display-only mode-line indicator, shown while a run is active, gives the short run id, stage, elapsed time, reviewer progress and a warning face for IDLE, heavy polling, BLOCKED or needs-you; it is not clickable
  - ERT tests in test/tradeoffs-trace-test.el cover the decision block rendering from a fixture (states, also-seen-by, no triggers), the trace line rendering including file change lines, and the pipeline/Time lines; the removed keys' tests are removed; make -C tradeoffs-trace ert passes
