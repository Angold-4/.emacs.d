#+TITLE: tradeoffs-trace dogfood plans

These plans finish the implementation plan (docs/tradeoffs-trace-plan.md)
by running tradeoffs-trace on itself. Each file is a single-phase plan
(the v1 conductor runs one phase per run). Run them in order; every run
publishes onto =feat/tradeoffs-trace-p4-dogfood=, so each one starts from
the previous run's published result.

| order | plan                          | what it adds                                          |
|-------+-------------------------------+-------------------------------------------------------|
|     1 | 2b-owner-commands.org         | DONE (run 4ec5e0f8, commit e0e80c0)                   |
|     2 | 2c-review-loop-speed.org      | DONE (commits 8af30b1, 8db4b60; live 50 s rounds)      |
|     3 | 2d-owner-input.org            | input box = the one way to intervene, transparently   |
|     4 | 3b-emacs-revise-history.org   | minimal readable decision view, trace, timing, pipeline |
|     5 | 4a-multiphase.org             | serial multi-phase runs, master reviewer continuity   |
|     6 | 4b-correct-earlier-phase.org  | corrections to an already integrated phase            |

* The owner's interface
Read the decision view (C-c m d); if a decision does not make sense, type into
the input box. That is the only way to intervene: it steers a running worker,
notes the next attempt, or corrects a phase waiting for you.

Writing a plan: see ~/orgw/PLAN_TEMPLATE.md.

* Running one
1. Open the plan file in the PR-20 Emacs, =C-c m r=.
2. Watch: =C-c m s= (trace | status | input); =C-c m d= once reviews start.
3. When the status shows DONE, BLOCKED or "needs you", hand the run id to the
   reviewing agent: "review tradeoffs-trace run <id>".

* Between runs
The runner is frozen while it builds itself. After a run is reviewed and
accepted, upgrade the runner to the new dogfood head before the next run:
: node ~/.tradeoffs-trace/runner/current/tradeoffs-trace/src/cli.ts runner install <sha>
Never upgrade while a run is in flight.
