* Phase 2c: review loop and speed
  :PROPERTIES:
  :ID:          p2c-review-loop-speed
  :CHECKS:      make -C tradeoffs-trace check
  :BOUNDARIES:  tradeoffs-trace/schemas/**
  :RESERVED:    the master-veto two-of-three voting rule; the acceptance predicate's clauses in src/core/predicate.ts
  :END:
  Goal: a phase whose candidate is correct must be able to reach ACCEPTED, and each round must be spent on work rather than waiting. The first real dogfood run (4ec5e0f8, plan 2b) showed two dead loops the worker cannot fix: votes on decision records from superseded candidates, and a master reviewer that never ballots on records the other reviewers discovered in parallel; and it showed about 60% of every worker attempt spent in full test-suite runs and sleep/tail polling. Priorities: the voting rule and acceptance predicate stay as designed (design §5.1, §6.3); correctness of the tally over speed; speed comes from removing wasted work, never from skipping a gate. Design references: docs/tradeoffs-trace.md §2 (roles), §3.3 (two-turn review), §5, §6.1, §7.2.
  Acceptance:
  - discovery barrier: all three reviewers finish turn 1 (submit_discovery) before any reviewer receives its turn-2 prompt, and every turn-2 prompt lists the same merged set of votable records (worker disclosures plus all reviewers' discoveries plus triggers); a test named discovery-barrier shows M ballots on a record that A discovered (observed: 16 records A and B discovered in round 2 had no ballot from M, so the tally failed on missing ballots)
  - tally liveness: the tally never counts as missing a ballot on a record the reviewer was not shown for the current candidate; a test named no-unshown-ballots asserts it
  - stale records: in a repair attempt the worker is shown its prior decisions by id and marks each kept, changed (new text) or withdrawn instead of re-disclosing; kept and changed records are bound to the new candidate (version bumped on change), withdrawn and unmarked records from superseded candidates are marked superseded and are not votable; a test named stale-decisions-not-votable asserts a record describing the old candidate cannot block acceptance (observed: B and A rejected 3 round-1 records as no longer true of the new code)
  - reviewer discoveries in turn 2 are matched: each reviewer states for each of its turn-1 discoveries which listed record it is the same choice as, or none; matched discoveries count as that reviewer confirming the record, not as new records (observed: 114 records in one run from rediscovery)
  - reviewers record in discovery only choices that change behaviour, interfaces, guarantees or cost, at most 5 per reviewer per round; implementation observations and advice go into findings or ballot rationales (observed: 23 of 33 reviewer records were implementation observations)
  - a reviewer raising a finding that is already open marks it "same as F-…" instead of a duplicate
  - the reviewer prompt distinguishes closing a finding as confirm repaired (the new candidate fixes it) from withdraw (the finding was wrong); the conductor records FINDING_CONFIRMED_REPAIRED for the former (observed: every fixed finding was closed as disproved)
  - a repair attempt resumes the same worker Pi session as the phase's first attempt (one session per role per phase), as design §6.1 requires (observed: attempt 2 ran in a new session directory)
  - worker speed: the worker prompt states that the conductor runs the phase CHECKS on a fresh checkout after submit_phase, so the worker runs only narrow tests for the files it changed; a make target test-fast (the unit, contract and effects tests, without the slow real-process conductor and crash tests) exists for that and the prompt names it; the phase CHECKS stay the full suite
  - the sh guard refuses commands that background work (&, nohup, setsid, disown) and sleep longer than 30 s, with a tool error explaining that the conductor runs checks and enforces deadlines (observed: nohup suite runs escaped the 10-minute deadline; 40% of attempt 1 was sleep/tail polling, 50% of attempt 2 was five full-suite runs)
  - worker and reviewer prompts ask for each decision's choice as one plain sentence of at most 20 words
  - tt state exposes, per record, the tally result for the current candidate (passed, failed with reason such as "M veto" or "missing ballot from M", suspended, pending, superseded) and the round number
  - all existing tests still pass
