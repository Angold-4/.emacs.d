* Phase 2c: owner input, model discipline
  :PROPERTIES:

  :CHECKS:      make -C tradeoffs-trace check

  Goal: the owner intervenes only through the Emacs input box, and every intervention is transparent: before sending, the input buffer states what sending will do now; after sending, the status buffer shows what actually happened. Worker and reviewer prompts are tightened with what the first real dogfood run (4ec5e0f8) showed about the model's behaviour. Design references: docs/tradeoffs-trace.md §7.4, §7.5, §9.3; plan 2b's inbox commands are the mechanism.
  Acceptance:
  - input sent while a worker attempt is running is delivered to that attempt as a Pi RPC steer (deliver.intent before sending, deliver.done on acknowledgement; after a crash between them the command is shown as delivery uncertain and never resent automatically)
  - input sent while no worker is running (checking, probing, reviewing) is a note delivered verbatim at the start of the next worker attempt
  - input sent while the phase is AWAITING_OWNER is an owner correction: it resolves the open owner requests, grants 3 repair rounds (independent of the exhausted budget) and starts a repair attempt whose prompt contains the text verbatim; the new candidate is checked, probed and reviewed as usual
  - input sent after the phase is DONE or BLOCKED is refused with the reason shown in the input buffer
  - the *tt-input* header line, recomputed on refresh, states which of these will happen right now and to which attempt; in Evil normal state RET sends, in insert state RET inserts a newline, C-c C-c sends from either state
  - the status buffer has an "Owner input" section listing each sent text with its recorded state (delivered, noted, correction started, refused: reason, delivery uncertain); a command the conductor has not picked up within 30 s is shown as "not picked up"
  - the worker prompt says the conductor runs the phase CHECKS itself on a fresh checkout after submit_phase, so the worker runs only the narrow tests for the files it changed, never the full suite
  - the sh guard refuses commands that background work (&, nohup, setsid, disown) with a tool error explaining that the conductor enforces per-command deadlines (observed: nohup test runs escaped the 10-minute deadline and the worker spent 40% of its attempt in sleep/tail polling)
  - worker and reviewer prompts ask for each decision's choice as one plain sentence of at most 20 words; the full reasoning belongs in whyItMatters and the alternatives
  - in turn 2 each reviewer states, for each of its turn-1 discoveries, which disclosed decision it is the same choice as (or none); matched discoveries are recorded as that reviewer confirming the decision, not as new decisions (observed: 114 decision records in one run from repeated rediscovery)
  - Emacs writes inbox command files atomically (write a temporary file in inbox/, then rename it to <id>.json), and the conductor retries a file it cannot parse on the next polls for at least 5 s before rejecting it; found by reviewer M in run 4ec5e0f8: with-temp-file plus a 1 s poll can read a partial file and reject the command permanently
  - tt stop <run> ends a run's conductor cleanly (agents terminated, lock released, stop event logged) and tt resume can continue it later
  - tests under tradeoffs-trace/test/ cover steer delivery and delivery uncertain (steer-uncertain), the AWAITING_OWNER correction path (correction-after-budget), refusal after DONE, the backgrounding guard and discovery matching; ERT tests cover the input header states and the Owner input section from a fixture
  - all existing tests still pass
